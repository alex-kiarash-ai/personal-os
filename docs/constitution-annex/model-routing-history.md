  **WHY, and it was not a cost decision:** the Moonshot org hit a NEGATIVE balance (`cash_balance -4.37`, `available_balance 0`) and every kimi-k3 call returned HTTP 429 *"Your account ... is suspended due to insufficient balance"*. That is an account suspension wearing a rate-limit status code, so no retry, backoff or spacing touches it: 60/60 calls failed at one request per 3 seconds (exec 3715). The same account had been recharged 8.34 USD on 08-05 and drained inside a day. **Read the 429 body before diagnosing a 429** - n8n discards the provider body on a thrown HTTP error, so the execution record shows only its canned "too many requests" text and the real reason is invisible there.
  **This was a provider migration, not a model-string swap** (the mirror image of the 07-27 move): the `Claude *` HTTP nodes were repointed from `api.moonshot.ai/v1/chat/completions` (httpHeaderAuth `OffvMkWR01zcpqxo`) back to `api.anthropic.com/v1/messages` (`predefinedCredentialType` `anthropicApi`, `anthropic-version: 2023-06-01`; #03/#32/eval use `Anthropic account` `XWuMgzQP0bY1hHuF`, #14 uses `Anthropic account 2` `GlSYkcT1yOArFWIR`); the Build nodes went from OpenAI `messages:[system,user]` + `reasoning_effort` back to an Anthropic top-level `system` BLOCK carrying a `cache_control` breakpoint + `thinking:{type:'adaptive'}` + `output_config:{effort:'high'}` + user-only `messages`; and the Parse nodes moved from `choices[0].message.content` to the TEXT blocks of `content[]` with Anthropic usage fields (`input_tokens`/`output_tokens`/`cache_creation_input_tokens`/`cache_read_input_tokens`), plus `stop_reason` handling for `max_tokens` and `refusal`. `max_tokens` stays 16384 because on this family it caps thinking AND visible text together.
  **The one non-obvious trap, and it would have failed silently:** adaptive thinking is ON BY DEFAULT on opus-5/sonnet-5, so `content[0]` is a THINKING block. A `content[0].text` reader returns empty on every call, and every job then fails the gate as a parse error - a total outage that looks like a model problem. The parse filters `type === 'text'` and joins, so it is correct with thinking on or off.
  **Prompt caching is back, and it is the real cost story:** the system prompt + master CV is ~9.3K chars of identical prefix on every job in a run, and Moonshot had no cache-write tier. With the `cache_control` breakpoint the second call onward bills that prefix at ~0.1x (measured on the live probe: 2277 cached-write tokens, 12 uncached input). List price is $5/$25 per M for opus-5 and $3/$15 for sonnet-5 ($2/$10 intro to 2026-08-31), against kimi's $3/$15.
  **Proven before and after the write, not asserted:** both Anthropic credentials probed live on all four candidate models (200 OK); the exact generated body shape probed against the real API on both models (200, cache write confirmed); the patched Parse nodes executed offline against healthy / thinking-first / refusal / truncated / n8n-error-item / markdown-fenced replies (35/35); and the **Writer Voice Eval re-run on claude-sonnet-5: 6/6 ALL PASS, 0 dashes, no AI tells**. Script + per-lane backups: `work/03-application-engine/config/apply-anthropic-migration-2026-08-07.js` (`--dry`, `--restore` and `--only=<id>` supported; backups `backup-before-anthropic-<id>-*.json`).
