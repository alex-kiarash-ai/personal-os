# /prompting - Plain English In, Senior-Level Prompt Out

Spec: work/26-prompting/CLAUDE.md (read it first; it defines the flow, the two prompt layers, the file lookup table, the task patterns, and the hard-case behaviors). Model layer: work/26-prompting/model-playbook.md (Anthropic's per-model prompting guidance, the file the spec points at). On-demand. Alex acts as a senior prompt engineering specialist: Shaheen speaks intent, Alex hands back a lean CONTEXT / INPUT / OUTPUT prompt for Claude Code.

Usage: `/prompting` (or with the request inline: `/prompting I want a workflow that watches my Gmail...`), or just say "write me a prompt for...".

## Steps (condensed; spec is authoritative)
1. **Step 0, overlap check.** Request vs the routing table / system/manifest.json. Substantially covered by an existing automation -> flag it in the gap round: extend or build new? Shaheen decides. Never silently rebuild a live system.
2. **Step 0.5, resolve the target model (Shaheen 2026-08-26).** Which model runs the prompt decides which model-layer lines go into it. In order: (a) he named one, use it; (b) the prompt targets an n8n node or a scheduled `claude -p` wrapper, so `system/manifest.json` `meta.model_routing` already fixes it (V6/V13 enforce that contract, an answer here can never override it), state which and why; (c) otherwise **ASK, every time** via AskUserQuestion, `Opus 5` (default, what an interactive session runs) or `Fable 5`, Other for Sonnet 5 / Haiku / a 4.x. The question rides as the FIRST question of the single gap round, and **that round fires even when the model is the only gap.**
3. **Extract intent** (voice input arrives messy; take it as-is, never ask him to repeat). Identify task type + one-off vs durable.
4. **Build the step sequence** from the task patterns in the spec. No permission-asking.
5. **Gap-check** (model, format, destination, MCPs, one-off vs durable, overlap resolution). **ONE batched round of questions in chat**, only real gaps, always ending with: "or say *defaults*."
6. **Assemble the prompt** per the spec's structure. **Universal layer, every prompt:** INPUT 1 = Identity (re-read the loaded soul core; pull full soul.md when the task's register is not in the card - gate-40 YES 2026-08-16; CLAUDE.md wins on conflict), INPUT 2 = Resources opening verbatim with "Identify the skills that are needed for the task and use them" + the resolved, NAMED skills/MCPs/file pointers, INPUT 3 = pattern steps. Pasted source material of ~20K tokens or more goes ABOVE the three headers in `<document>` tags with the ask last (playbook 2.6, up to 30 percent better), with a quote-first instruction. OUTPUT 1 states the deliverable **and its length** ("match the length to what the task needs, no filler sections, no redundant summaries, no boilerplate"; name a real band where one exists). OUTPUT ends with the real Close-Out Gate reference, never a paraphrase. Pointer style throughout: reference files, never restate their contents.
7. **Then swap in the resolved model's addendum** from the spec's model layer. This is the half that is NOT universal, and three of its lines invert between models. Opus 5 gets the scope line ("deliver this task at the scope asked..."), the conciseness line, and the delegation cap (never a subagent to verify work already finished). Fable 5 gets the boundaries block, the anti-over-engineering block, the lead-with-the-outcome line, the grounded-progress block, and delegation turned UP rather than capped. Never ship one model's lines under the other's label. Research still routes through /research-team (#04) on every model, and a relay Shaheen dictated himself is exempt from every delegation rule.
8. **Deliver lean:** one markdown block, three headers, zero padding. Save to outputs/prompting/YYYY-MM-DD/{slug}.md. One line rides OUTSIDE the block: `Built for: <model> - Suggested effort: <low|medium|high|xhigh>`, the effort taken from the resolved model's row and never carried across from another model.
9. **Offer once:** "run it now?" Yes -> execute in this session as Alex. If the resolved model is not what this session runs, say so in one line first.

## Hard constraints
Overlap check always first · **target model resolved before assembly, asked every time it is unstated** · one gap round max, defaults skip always offered · the verbatim skills sentence in every INPUT · MANDATORY skill bindings named, never generic · pointer style, no retyped facts · real gates referenced, never paraphrased · lean delivery, no padding · durable automations route through /new (registry-first) · **the model-layer lines come from the resolved model's block, never applied unconditionally** (a model-layer rule applied to every model is a bug with a delay on it, and it stays invisible because the prompt still reads well) · **verification hygiene: no generic "verify your work" step ever; verification only as an external-system read-back, a pixel/render check, or a named gate** (Opus 5 self-checks; a blanket instruction just pays twice). The one model-dependent exception: on Fable 5 a NAMED fresh-context verifier subagent at a stated interval is allowed on long runs (playbook 4.12), because a mechanism with a target is not a blanket instruction.
